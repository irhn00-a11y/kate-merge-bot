# ケイトの冒険 自動マージbot

## 準備（PC側・初回のみ）
1. Android SDK Platform-Tools（adb）を入れて PATH を通す
2. スマホ：設定 → 端末情報 → ビルド番号を7回タップ → 開発者オプション →「USBデバッグ」ON
   - **「USBデバッグ（セキュリティ設定）」もON**（Xiaomi/POCO系はこれが無いとタップ入力が拒否される）
3. USB接続して `adb devices` で `device` と出ればOK（ワイヤレスデバッグでも可）
4. `pip install opencv-python numpy`
5. 見る用：`scrcpy` でミラーリング（botの動作とは独立）

## 使い方
```
python kate_merge_bot.py --analyze shot.jpg   # スクショ1枚で認識テスト（ADB不要）
python kate_merge_bot.py --dry-run            # 実機を読むだけ、矢印表示のみ
python kate_merge_bot.py                      # 自動マージ開始（Ctrl+C停止）
python kate_merge_bot.py --produce 5 3        # ペア切れでオーブン(列5,行3)をタップして補充
```
マス座標は左上が (0,0)、列→右、行→下。

## 仕組み
screencap → 7x9に切る → 空き/段ボール/瓶/アイテムに分類 → 色ヒスト＋シルエットで同種判定 → 1手スワイプ → 毎回読み直し

## 検証状況
- 2026-11-05 のスクショ1枚で：63マスの分類全一致、ペア6組すべて正解（小麦粉×2、バター×2、スコップ×2）
- **実機でのADB操作は未検証**

## 調整ポイント（kate_merge_bot.py 冒頭）
- `BOARD`：盤面の位置がズレる場合
- `SAME_THRESHOLD`：違う物をくっつける→上げる／同じ物を見逃す→下げる
- `SWIPE_MS` / `WAIT_AFTER_MERGE`：速度。上げるほど「見て楽しい」寄り

## 既知の弱点
- レベル違いの同種（バター1とバター2など）を同一視する可能性。見た目が大きく違えば問題なし
- 瓶の中身への合体（解放）、ポップアップ、エネルギー切れは未対応
- 使うときは規約上の自己責任で（オンラインランキング系は特に）

## 注文保護モード（デフォルトON）
- キャラ下のクリーム色パネルから注文アイコンを毎回読み取り、盤面で同じ物は **ORDER（黄枠）として触らない**
- 判定：注文アイコンを拡大したマスク付きテンプレートマッチ。一致度 ≥ `ORDER_THRESHOLD`(0.60) かつ その注文の最高一致から `ORDER_MARGIN`(0.12) 以内
- `--ignore-orders` で無効化、`--max-merges N` でN回マージしたら停止
- 検証：実スクショ（注文=サンドイッチ・ケーキポップ、盤面に無し）→ 保護0件で正解。
  盤面アイテムを注文欄に合成したテスト7種（バター/小麦粉/スコップ/トースト/オーブン/計量カップ/生地）→ 全て該当アイテムを保護。
  小麦粉テストのみ計量カップも巻き添え保護（安全側の誤り）
- 未検証：実際の注文アイコンが盤面と同じ絵柄か、注文が複数キャラ並ぶ時の読み取り
- 未対応：注文品を作るための「レシピ逆算」、納品タップ

# 矢印パズル自動解答bot（arrow_bot.py）
棒を矢印の向きに抜いて全部逃がすゲーム用。adb接続・画面取得は kate_merge_bot.py を流用（同じフォルダに置く）。

## 使い方
```
python arrow_bot.py --analyze shot.jpg   # スクショ1枚を解いて arrow_solution.png（ADB不要）
python arrow_bot.py --dry-run            # 実機を読んで解答画像を保存するだけ（タップしない）
python arrow_bot.py --step --levels 1    # 1本押すごとに読み直す慎重モードで1面だけ
python arrow_bot.py                      # 本番。面が消えたら次の面を待つ（次へボタンは自分で押す）
```
- Termuxでは解答画像を `Pictures/arrow_bot_latest.png` に保存（オレンジ数字=タップ順、緑丸=矢印の頭）
- 停止：Ctrl+C か `touch ~/arrow_stop`。adbが切れたら `python kate_merge_bot.py --connect` で再接続

## 仕組み
1. 黒い線の画素から等間隔グリッドを推定（1面の間は固定。棒が減ると推定がぶれるため）
2. マスの交点と交点間の線で棒をつなぎ、端点の形（先端の突き出し＋左右の羽）で頭を判定
3. 貪欲法：頭の向きの直線上に他の棒がない棒を抜く、を繰り返す。抜いても他を塞がないので探索不要
4. 同時に抜ける棒を「波」にまとめ、波の中は `--tap-wait`(0.12秒)、波の間は `--wave-wait`(0.4秒) 空けてタップ
5. 読み取り不良（分岐・頭が曖昧）が1本でもあればタップしない。`--max-bad`(5)回続いたら停止

## 検証状況（2026-11-05）

- 720x1560縮小・JPEG劣化でも同じ結果
- `tools/arrow_sim.py`：仮想ゲーム（押した棒の先が塞がっていればミス扱い）で一括モード・慎重モードとも 37/37本、ミス0
- 頭を1個消した画像 → その棒だけ不良判定、タップせず5回で停止（安全側）
- **実機でのタップは未検証**

## 未確認・既知の弱点
- 頭の先に自分の体がある場合（渦巻きの内向き）は「自分の体は無視」で計算。実機での扱いは要確認
- 棒同士の交差・T字は未対応（不良判定で止まる）
- ダークテーマ・背景が単色でない面は未対応（`DARK` しきい値で線を判定している）
- 抜けるアニメ中のタップが無視される場合は `--wave-wait` を伸ばすか `--step` を使う
